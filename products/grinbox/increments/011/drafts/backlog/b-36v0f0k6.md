# Time-delayed archive

Archive N hours after receipt rather than at triage time, for message classes
that are useful briefly and worthless after (verification codes, day-of delivery
notices). Needs a small scheduled sweep (shares scheduling infrastructure with
the digest).

From the roadmap grinbox carried while it was built by hand, recorded here as it
stood. That file went with the rest of the source when the code moved into the opus
workspace, and the capture that produced increments 001-007 recorded the design of
what existed rather than what was still wanted, so this was held nowhere afterwards.

A concrete case from running the digests (2026-08-11): the digest mails grinbox itself
sends are re-ingested as ordinary messages and pile up in the inbox — wanted while
fresh, archive-worthy after a few days. Arrival-time archiving cannot express this.
Since 009 an edition is an ordinary operator instance carrying its schedule, so a
delayed archive could be a second schedule-triggered operator type on the same
heartbeat.
