# mctest effect display-name probe results

Observed output from running `effect-name-probe-pack` against a real Bedrock dedicated server:
`mctest5:effectnames` (the effect type × amplifier → display-name mapping) and
`mctest5:effectbounds` (the accepted amplifier and duration ranges). Each set was run three times.
The probes report what the engine did; nothing here is an assertion about what the fake should do.

## Run provenance

| Server | `itzg/minecraft-bedrock-server`, Bedrock dedicated **1.26.31.1** |

| Source | stationary armor stand at `(38.5, 81, 22.5)`, on a placed stone platform inside the `mctest` ticking area |
| Coverage | 3 × each set, no `PROBE CRASHED` lines, every `complete` line present |

Installed alongside the six earlier packs and loaded as `[06] mc-test-lib effect display-name
probes`. It shares the `mctest5:` namespace with `return-value-probe-pack` but registers different
command names, and the boot log shows no registration conflict.

**Reproducibility is exact.** Normalising only the log timestamp and the spawned subject's entity
id, the **entire body** of each set is byte-identical across its three runs (md5 match) — not just
the summary blocks. `minecraft:speed` reads `"Speed"` at amplifier 0 and `"Speed II"` at amplifier
1, matching `f:live-effect-fields-populated`, so the run is measuring the same thing the record
already carries.

## The display name stops tracking the amplifier at 6

37 types × 7 amplifiers = **259 cells, 259 `READ-OK`**, no unreadable name and no type that carries
one name across all amplifiers. The mapping is regular:

| amplifier | display name |
|---|---|
| 0 | base name, no numeral — `"Speed"` |
| 1–5 | base name + Roman numeral of *amplifier + 1* — `"Speed II"` … `"Speed VI"` |
| 6 | **base name again, no numeral** — `"Speed"` |

**The reversion at amplifier 6 holds for all 37 types without exception** (checked cell by cell:
37 types where the amplifier-6 name equals the amplifier-0 name, zero exceptions). The
`effectbounds` sweep carries it further: across the full accepted amplifier range `0…255` there are
only **6 distinct names**, and `highest-amplifier-whose-name-differs-from-the-next-lower=6`. From
amplifier 6 upward every amplifier reads the bare base name.

So a computed display name is possible but must special-case the tail: numeral for amplifiers 1–5,
bare base name for 0 **and for everything from 6 up**. A naive `base + roman(amplifier + 1)` is
correct for exactly five of the 256 accepted amplifiers.

### One name is not clean data

`minecraft:breath_of_the_nautilus` reads with a **leading space** at every amplifier —
`" Breath of the Nautilus"`, `" Breath of the Nautilus II"`, and so on. It is the only type with
leading or trailing whitespace in its name, it is identical across all three runs, and it comes
straight from the engine's localisation string. A fake that stores observed names reproduces it; a
fake that computes them will not, unless the base name is stored verbatim including the space.

## Accepted ranges, and no clamping anywhere

Identical in 3/3 runs:

| argument | accepted | first rejected | error |
|---|---|---|---|
| amplifier | `0 … 255` | `256` (and `-1`) | `ArgumentOutOfBoundsError`, `minValue=0 maxValue=255` |
| duration | `1 … 20000000` | `0`, negatives, and `20000001` | `ArgumentOutOfBoundsError`, `minValue=1 maxValue=20000000` |

**Every accepted value reads back as the value requested** — `read-back-echoes-request up-to=255
first-divergence=none` for amplifier, and the duration read-back list echoes each of
`1, 2, 20, 200, 19999999, 20000000` exactly. Nothing is clamped into range: a value is either
accepted verbatim or rejected with `ArgumentOutOfBoundsError`. That distinction is the one the
probe was built to separate, and it comes out cleanly on both arguments.

Note that duration's minimum is **1, not 0** — a zero duration is rejected rather than treated as
an instantaneous or absent effect.

## Run-validity notes

- **`n = 3`, and reproducible at the whole-log level** rather than merely at the summary level. The
  only fields that vary between runs are the timestamp and the subject entity id.
- `SUMMARY subject-respawns=0` in every `effectnames` run: one subject survived all 259
  applications, so no cell was measured against a different entity than its neighbours.
- **The `/mctest5:effectnames` and `/mctest5:effectbounds` slash commands are unexercised.** All
  runs went through the `scriptevent` fallback, so the custom-command path is only known not to
  have thrown at registration — the same residual every earlier pack carries.
- **No player was connected.** Neither set reads a player.
- **Raw-log inclusion is partial, deliberately.** `effectnames` emits 313 lines per run and
  `effectbounds` 81, and the three runs are byte-identical after normalisation. Run 1 of each set is
  reproduced in full below; for runs 2 and 3 only the `SUMMARY` blocks are included, with the md5
  equality recorded above standing for the bodies. Nothing was dropped for being inconvenient — the
  omitted lines are identical to the ones shown.
