# mctest arity, expiry, handler-write and filter probe results

Observed output from running `arity-expiry-and-filter-probe-pack` against a real Bedrock dedicated
server: `mctest8:arity`, `mctest8:expiry`, `mctest8:handlerwrite` and `mctest8:filters`. Each set
was run three times. The probes report what the engine did; nothing here is an assertion about what
the fake should do.

**Reproducibility.** Normalising the log timestamp and entity ids, each set's entire body is

## `arity` — the ruling is contradicted, unanimously

```
HEADLINE max+1  SURPLUS-THREW=18/18  SURPLUS-ACCEPTED=0/18  accepted=[]
HEADLINE zero-arity-members  threw=5/5
```

Per the README's own reading, **`SURPLUS-THREW` on any member contradicts the ruling that a
generated member checks only the minimum and lets extra arguments through.** It fires on **every one
of the 18 members**, and on all 5 zero-arity members separately, with `SURPLUS-THREW-TYPE-ERROR` in
each case.

The engine enforces a maximum arity as well as a minimum. A generated member that forwards surplus
arguments will not match it, and the ruling needs replacing rather than narrowing — there is no
subset of members for which it holds.

The arity design carried its weight here: each member's `[control]` line reads `CONTROL-RETURNED`
(18/18), so the surplus throws are the surplus argument being rejected and not the call being
malformed to begin with.

## `expiry` — the ruling is confirmed

```
HEADLINE duration-0-ever-readable=false  last-readable-duration-always-1=true
```

Both halves hold, in 3/3 runs. The effect is removed on the tick its duration reaches 0, so the last
readable duration is 1 and 0 is never observable. The second headline pins the disappearance exactly
at the requested duration for every case:

| requested | first absent tick |
|---|---|
| 3 | 3 |
| 5 | 5 |
| 8 | 8 |

Two repeats per duration, `sources-agree` throughout. Nothing here contradicts the spec.

## `handlerwrite` — 7 of 11 match, and the four that do not are all out-of-range writes

```
HEADLINE matches-spec=7/11
contradicting=[above-max, far-above-max, not-a-number, infinity]
```

The spec truncates the write toward zero, bounds-checks 1…20000000, and produces **no effect** when
the result is out of range. Every in-range and truncation case matches. All four failures are cases
where the spec predicts `NO-EFFECT` and the engine produced one:

| case | spec predicts | observed |
|---|---|---|
| `above-max` (20000001) | `NO-EFFECT` | **`WRITE-TOOK-AS-WRITTEN-20000001`** — the effect carries a duration one above the documented maximum |
| `far-above-max` | `NO-EFFECT` | `EFFECT-PRESENT-OTHER-DURATION-20000000` — **clamped** to the maximum |
| `not-a-number` | `NO-EFFECT` | `WRITE-IGNORED` — the effect carries the duration the probe requested |
| `infinity` | `NO-EFFECT` | `WRITE-IGNORED` — likewise |

Three distinct behaviours, none of them "no effect": a value one above the maximum is **taken
verbatim**, a far larger one is **clamped**, and a non-numeric write is **ignored** so the
originally-requested duration survives. Note the contrast with `addEffect`'s own argument
validation, where the earlier effect-bounds probe found 20000001 rejected with
`ArgumentOutOfBoundsError` and no clamping anywhere — the before-event field write and the call
argument are validated differently.

## `filters` — INTERSECT confirmed, five readings out of five

Both run-validity gates pass in 3/3 runs: the unfiltered control received all four hurt events and
all three die events, and the both-fields-match handler fired. The readings are therefore live
rather than vacuous.

| crossing | received | reading |
|---|---|---|
| `entityTypes=[sheep] AND cause=[lava]` | only `sheepA-lava-no-damager`, no `entityAttack` event | **INTERSECT** |
| `entityTypes=[cow] AND cause=[lava]` | nothing | **INTERSECT** |
| `entities=[sheepA] AND entityTypes=[cow]` | nothing | **INTERSECT** |
| `entityTypes=[cow] AND entityFilter={tags}` | nothing | **INTERSECT** |
| die: `entityTypes=[sheep] AND entities=[cowVictim]` | nothing | **INTERSECT** |
| die: `entityTypes=[sheep] AND entities=[sheepOther]` | `sheepOther` alone | **INTERSECT** |

**The `entityFilter.tags` gate matters and it passed.** `filter-tag-sheepA` alone received
`["sheepA-entityAttack-by-pig","sheepA-lava-no-damager"]`, so the tag filter is honoured by the
engine and the crossed `types-cow+filter-tag-sheepA` case is a real observation rather than a void
one. That was the case the decision's union falsifier names, and it is now answered on evidence.

Two further readings, both matching what the spec assumes:

- **`entityTypes` reads the hurt entity, not the damaging one.** `types-pig` received nothing
  although a pig was the damager in three of four events.
- **`entities` is an instance filter, not a type filter.** `entities-sheepA` received only sheepA's
  two events and `entities-sheepB` only sheepB's one, with no crossover; the same holds for the two
  sheep deaths.

### The id-format check became a finding

Subscribing `entityTypes` both ways side by side was framed as a run-validity check. It is not
neutral:

| handler | received |
|---|---|
| `types-sheep` (`minecraft:sheep`) | 3 events |
| `types-sheep-unqualified` (`sheep`) | **nothing** |

**`entityTypes` requires the namespaced id.** A bare `sheep` matches no event at all rather than
matching everything or throwing. This extends the surface-dependence already recorded for
`namespace-prefix-is-optional`: the prefix is optional on `addEffect`, `getEffect`, `spawnEntity`
and `getComponent`, mandatory on `triggerEvent`, and now mandatory on subscribe-filter
`entityTypes`. A fake that normalises ids on entry would silently accept a filter the engine
ignores.

## Run-validity notes

- **`n = 3` per set**, byte-identical across runs after normalisation.
- **Every `[control]` line in `arity` reads `CONTROL-RETURNED`** (18/18), so each member's surplus
  case is a rejection of the surplus argument rather than a malformed call.
- **Every `handlerwrite` case reads `handler-ran=true`** (11/11), so no contradiction is a handler
  that failed to fire.
- **Both `filters` `RUN-VALIDITY` gates pass**, so no filter reading is vacuous.
- **The `/mctest8:*` slash commands are unexercised.** All 12 runs went through the `scriptevent`
  fallback — the residual every pack in this series carries.
- **No player was connected.** No set reads a player.
