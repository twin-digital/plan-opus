# A session can leave an agent an accepted entry nobody has stated

`d-octrdz0j` has a requirement- or decision-routed answer close its question and write a
placeholder entry carrying the generated id and the owner's answer text, "for the owner to
state". `d-k85itgcv` gives that entry `accepted` where the owner authored it.

So an agent returning to a branch after a session can find a new, accepted, under-stated entry it
did not write — already counted as settled by the landing gate, since the gate reads `proposed`
and open questions only. Whether finishing the statement is the agent's job, and whether
rewriting the text of an accepted entry needs the owner back, is unstated.

Predates the ratify-view increment, but that increment is what puts agents and sessions on the
same branch routinely. Found by the increment-skill surveyor on 2026-08-05.
