# Minecraft dev workflow: Design Brief

The dev workflow is the harness a pack author runs to iterate on Bedrock behavior packs against a real, disposable server. The daily feel it should produce: one command brings up a server and starts watching; you edit a pack's source, save, and the change is live in-game within a second or two without kicking anyone; you close the loop and the server keeps running so you can reattach; and adding a whole new pack needs no edit to the harness because packs are discovered, not listed. It is a developer-experience tool — nothing it does is shipped, and its only job is to make the edit→see cycle short and the throwaway cost low.

It exists because Bedrock offers no native hot-reload path for a monorepo of packs: a pack must be copied into the server's `development_behavior_packs` pool, *activated* by a separate per-world list that is only read at world load, and then `/reload`ed — and the pieces have sharply different refresh semantics (script edits reload live; a new pack, a renamed folder, or an activation change need a server restart). A prototype on the `@twin-digital/monorepo` `ci-turbo-caching` branch wired all of this end-to-end and, through several review rounds, learned where the sharp edges are. This design is a clean, spec-first rebuild of that harness: the durable inputs below capture what that prototype established as fact and what the owner wants as outcome, so the design that follows can choose its structure freely on solid ground rather than re-deriving the reality.

What this brief deliberately leaves open for the design to decide: the **deploy transport** — whether packs reach the running container via Docker Compose's `develop.watch` or a direct Node/API push — and how the loop's processes are supervised. The captured facts constrain those choices (compose watch cannot discover packs and has awkward path rules; `compose cp` works against a remote daemon) but do not settle them; the prototype tried compose watch first and then replaced it, and a fresh design should weigh that trade on the evidence rather than inherit the answer.
